# B. Sewage alert system

**Goal:** A reliable, real-time **text-alert** system for combined-sewer-overflow (CSO / sewage dumping) events in San Francisco, built for the Surfrider SF Blue Water Task Force.

## Snapshot — where it stands today

- **Detection works.** `core/sfpuc_api.py` pulls live station status + CSO flags from SFPUC's internal LIMS API; `core/monitoring.py` adds SF Gov bacteria data + AB-411 logic; `core/weather_tides.py` adds rain/tide context.
- **Channels exist.** `core/notifiers.py` supports Twilio SMS, free email-to-SMS gateways, SMTP email, Slack, Discord, and console.
- **Subscriptions work per-site.** `core/subscriptions.py` + `data/subscriptions.json`, with targeted dispatch in `core/cso_alerts.py`.
- **Dashboard runs locally.** `dashboard.py` serves `localhost:8080` via Python's single-threaded stdlib server; HTML is generated inline (~1,695 lines).
- **Test harness exists.** Simulated CSO events (`SimulatedCSOStore`) let you fire fake events without waiting for a real one.

**Central gap:** detection and dispatch are **manual** — a real CSO only goes out when someone clicks the dashboard button or runs `run_subscription_alerts.py` by hand. Nothing polls SFPUC on a schedule, remembers what it already sent, or runs unattended. State is local JSON files, and there are no tests. Most items below build toward closing that loop.

# C. Data comparison dashboard

**Goal:** Compare water-quality results for the same SF beaches between the two independent monitoring programs — the **Surfrider Blue Water Task Force** volunteer lab and **public city data** (SF Gov Open Data + SFPUC) — to build trust, surface divergence, and tell a public story about beach safety.

- Compares the **6** sites BWTF currently publishes for SF: Aquatic Park, Baker Beach at Lobos Creek, China Beach, Crissy Field East, Ocean Beach at Lincoln Way, Ocean Beach at Vicente St.

## Site Report Card (city-data analysis page)
- [x] **Shipped** — `/analysis`: per-site exceedance rates from the city's lab data (DataSF `v3fv-x3ux`), ranked, with date-range controls (dataset floor 2020-07-27) and a **weekly-regime vs all-samples** toggle. Weekly regime = the first sample of each site-week (the city's Monday cadence), excluding post-exceedance resamples — those cluster around contamination events and can double an event-heavy site's rate (Islais Creek: 30% all-samples vs 15.5% weekly; Mission Creek falls from co-worst to mid-pack). Sporadically-sampled stations (Fort Funston, OB Vicente, OB Pacheco) are flagged and listed unranked. Motivated by the BWTF lead's east-side / India Basin expansion question; the written answer lives at `reports/2026-08_eastside_site_analysis.html`.
- [ ] **Quantify the resample data without contaminating base rates.** Dropping resamples (weekly mode) throws away real information: how long contamination *persists* after an event. Direction: group consecutive exceedances into **episodes** and report episode *frequency* (episodes/yr) and *duration* (days until the first clean resample) as separate metrics alongside the weekly base rate — resamples inform episode metrics, never week-by-week rates. Could cross-validate episode durations against our own real-time event windows (`/cso-history` clears, migration 006). Mission Creek is the motivating case: mid-pack weekly rate (12.5%) but long episodes (32.7% of all tests fail).
- [ ] Fold BWTF's own volunteer results into the report card as a second series (same weekly cadence — direct apples-to-apples with the city's weekly-regime numbers).

# D. SF sewage forecaster

**Goal:** Predict CSO (combined sewer overflow) risk in SF *before* discharges happen, from rainfall — advance warning rather than after-the-fact beach postings.

## Shipped (brought in from the prototype)
- Lives at `features/forecast/` (moved intact from the standalone `sf_sewage_forecast` repo): scikit-learn models (per-basin + citywide `.pkl`), rainfall/CSO collectors (`src/`), basin config, and the live engine (`live_dashboard.py`).
- Served at `/forecast` via `features/forecast/page.py`, which wraps the engine (`LiveData`) and reuses its HTML; APIs namespaced under `/forecast/api/*`. A background thread refreshes predictions every 30 min.
- Lazy-loaded: needs the ML extras in `requirements.txt`; without them the page shows an install notice and the rest of the app is unaffected.

## Next steps
- [x] **Ground-truth CSD event dataset acquired (2026-08-21)** — 1,007 per-event discharge records (Oct 2016 – Oct 2025) scraped from SFPUC monthly SMRs on CIWQS, with a monthly coverage grid and 2013–16 Bayside legacy hours: `features/forecast/data/csd/` (see NOTES.md for schema/gaps + `records_request_draft.md` for extending it). Measured against it, the old bacteria proxy label was **79% precision / 50% recall** — it missed half of real events.
- [x] **Forecast v2 shipped to prod (2026-08-21)** — retrained on real events, two-stage risk (P(discharge) × measured persistence by discharge size), observed SFPUC CSO onsets from the Supabase alert_log override past-day probabilities, `cso_events.py` retired. Verified on Vercel + Railway.
- [x] **Forecast v2.1 (2026-08-21)** — hourly peak-intensity features (`rain_max1h/3h/6h`, Open-Meteo on both train and inference sides): holdout PR-AUC citywide 0.911 / Westside 0.828 / North Shore 0.790 / Southeast 0.812, zero critical false negatives. Persistence-null baseline added to the eval.

- [x] **Model selection infrastructure + weights-model candidate (2026-09-25; v4 stays served untouched)** — `src/models/leaderboard.py` fits candidate families × rain sources per basin and scores them exactly as the trainer does (pre-holdout leave-one-season-out CV, then the Jul 2023 → Oct 2025 holdout): `gb` = the production family, `logit` = a weights model (19 features + hinge terms at the rain knots → standardise → L2 logistic, C by pre-holdout CV); sources = NOAA pair, local gauge, CoCoRaHS Potrero (`src/collectors/cocorahs.py`, as filed and shifted −1 day), three-gauge mean.
