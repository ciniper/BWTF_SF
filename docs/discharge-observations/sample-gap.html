What the plan changes

  1. Read getCSV once per watcher run. It's one call for every station, in the same row shape DataSF uses.
  2. For each station, day and bacteria type, use DataSF's value when it has one, otherwise the getCSV value marked early. After DataSF's nightly load the early marks disappear on their own. Since 10/1 all 396 overlapping results match exactly.
  3. Remember when each early number first appeared, so the popover can say "lab results, in at 1:14 PM", and show missing bacteria types as "pending".
  4. Decide "new sample waiting" by comparing dates: getCSV has a newer sample than we show. No more guessing from posting changes.

Fixes the false "unpublished" alarm

On 11/13 Baker was posted as a precaution after a discharge. Our site read the posting as a lab result and said "2 new samples unpublished". With the date comparison, a posting alone never claims a waiting sample.

Shows storm-only stations

Vicente, Pacheco and Fort Funston are sampled only after storms. Their results appear in getCSV the same way as the routine stations.

What it can't fix

If SFPUC never samples a discharge, there is no row. On 11/13 China Beach had three pipes flowing, no City sample, and a Surfrider result of 6,131. Only our forecast and field reports catch that.

Held until the recorder finishes on Friday 11/20: emailing on early numbers. A published value has already been corrected once (Mission Creek's 11/13 total coliform, three days later), and SFPUC posts on preliminary counts we can't see.

Related: repeat discharge emails (rule decided 11/17, held)

On 11/17 SFPUC took Lincoln's discharge flag down at 8:34 AM and put it back at 9:11 AM. Our alert sender only compares each minute with the minute before, so the flag coming back counted as a new discharge and emailed again. Fort Funston did the same thing: off at 8:24 AM, back at 9:27 AM.

Rule: if a station already had a discharge flag earlier the same Pacific calendar day, it doesn't send another discharge email that day. A flag that comes back the next day emails as usual, so a real new discharge after SFPUC clears the flag still reaches people. We still record every flag change. Only the email is skipped.

The rule has to look at when the flag was up, not when we last emailed. Lincoln's and Fort Funston's earlier discharge emails went out on Friday 11/13, so "already emailed today" would have caught neither.
